# 实现与验收状态

更新：2026-10-09。本文件区分代码已实现、本地模拟验证和真实租户验收；模拟成功不等于真实消息覆盖或送达。

## 已实现

- 两个独立仓库：React/TypeScript Web、FastAPI/PostgreSQL 后端，独立提交说明及必要注释。
- 员工设置、每日计划、暂停/停用、手动执行、任务历史/详情；管理员授权用户、用户任务跳转、日期范围筛选、健康状态。页面只显示运行元数据。
- 演示首页提供 A/B/管理员入口；缺少真实应用配置时不跳转空 client_id 授权 URL。不同浏览器各自登录，标签页共享会话。
- Session、CSRF、公司/用户/角色隔离；网页登录与消息授权分开；state 浏览器绑定、一次性消费和 AES-GCM 用户绑定凭证。
- 三路消息搜索、分页、notice 时间窗细分、T+60秒尾部复查、直接 @筛选、会话/话题上下文及本地时间边界过滤。仍无法证明飞书搜索索引没有遗漏。
- 小时级凭证保活；授权失效按 auth_epoch 去重提醒；轮换锁与不确定刷新处理。
- 持久化任务、手动幂等/限频、每日排期、停机错过标记、两执行槽位；单 runner 选主、任务租约/心跳/fencing、原始截止时间保持。
- 固定分段载荷、UUID、发送意图和受控重试；生产载荷限 tmpfs，24小时清理。丢失载荷且曾发送的任务保留失败/不确定，不重新生成报告盲目重发；不承诺 exactly-once。
- 分块抽取、合并与重复项去重、来源校验、负责人/截止时间原文约束、静态卡片及字节上限。来源引用仅用于内部校验；按用户最新要求，报告不展示来源编号、会话/消息 ID 或定位附录。
- 单任务模型预算覆盖抽取、合并和修复；当前按 UTF-8 字节和输出上限保守预留，不能代替供应商账单/token 实测。
- 管理员访问按响应结果审计，包含拒绝/不存在；仅记路由模板，不保存搜索词。阶段耗时、分类重试、心跳和积压健康检查。
- 配置加密备份/空库恢复、7天备份保留、恢复后强制重新授权和暂停计划；联合发布镜像 digest/契约/迁移校验、CI 镜像构建、容器健康探针。

## 2026-10-09 模型失败排查与修复

- 历史失败仅记录 `MODEL_OUTPUT_INVALID`，没有保存模型正文，无法精确还原历史两次响应。经用户单次授权，在内存中重放原统计窗口，不发送报告、不保存消息或模型正文。
- 原实现真实重放复现两次 JSON 解析失败和一次读取超时，重试后完成。HTTP 200 / finish_reason=stop 不代表内容符合应用 JSON schema。
- Kimi K3 请求启用 JSON Mode，使用 max_completion_tokens；截断时在任务预算内提高一次输出上限。保留结构、来源和合并完整性校验。
- 网络、鉴权、限流、截断、JSON schema、来源和合并错误分别记录静态安全错误码；首轮失败原因记入 retry_counts。鉴权/请求参数错误不盲目重试，网络重试不追加格式修复提示。
- 修复后的同批真实消息完成抽取、合并及最终校验；两批抽取均一次通过，合并仍发生一次重试。此次诊断未调用消息发送接口，历史失败任务保持原记录，不等同于真实送达验收。
- 57 项后端测试通过（独立 summary_test、虚构租户），Ruff / mypy / Alembic 一致性检查通过。生产时延和两用户送达仍需验收。
